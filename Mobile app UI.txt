## Important hardware logic

FloodGuard uses a 12 V solar-battery system.

The Left RTU and Right RTU use an LVD circuit. When battery voltage falls below the preset protection threshold, the LVD may switch off the RTU load to prevent deep discharge.

The Left RTU and Right RTU battery status are detected through an LM393 voltage-comparator digital output. Therefore:

* Do not show numerical RTU voltage values.
* Do not show values such as `12.4 V`.
* Only show `OK` or `LOW`.
* Display RTU communication/power status separately as `ON` or `OFF`.

This distinction is important:

* `RTU Status: ON` means the RTU is responding or detected as active.
* `RTU Status: OFF` means the RTU is not active or not responding. This may be caused by LVD cutoff, battery depletion, communication loss, wiring fault, or another issue.
* `RTU Battery: OK` means the LM393 digital comparator indicates voltage is above the preset threshold.
* `RTU Battery: LOW` means the comparator indicates voltage is below the preset threshold.

## Water-level range

This app is for the FloodGuard application. Use:

* Minimum water level: `0 mm`
* Maximum water level: `1000 mm`

Do not use metres on this dashboard.

Show all current levels, alert levels, and danger levels in millimetres.

## Dashboard layout

### 1. Header

At the top of the dashboard show:

* Title: `Site Name - <Selected Location Name>`
* A dropdown selector containing predefined site locations
* Current date
* Live current time
* Optional small refresh indicator or last-updated timestamp

When a different location is selected, refresh all dashboard values using the selected site's data.

### 2. Main monitoring section

On desktop and larger tablet screens, split the main area into two columns.

On narrow mobile screens, stack the two panels vertically.

#### Left panel: animated water-level vessel

Show a visually attractive vessel or flood-water chamber.

Requirements:

* Display water filled inside the vessel according to the current level.
* Animate the water surface gently.
* Add subtle splash or wave animation so the water appears to rise naturally.
* Animate the water level smoothly whenever the value changes.
* Use a scale from `0 mm` to `1000 mm`.
* Show the current water level prominently below or inside the vessel.
* Draw an orange horizontal line for the configured alert threshold.
* Draw a red horizontal line for the configured danger threshold.
* Label the lines clearly:

  * `ALERT`
  * `DANGER`
* Ensure the vessel still looks clear on a small phone screen.
* Respect `prefers-reduced-motion`; reduce animation if the user has disabled motion effects.

Example display:

* Current level: `420 mm`
* Orange alert threshold: `600 mm`
* Red danger threshold: `800 mm`

#### Right panel: site and infrastructure status

Show a compact list of status cards:

* Device ID
* Device health: `WORKING` / `FAULTY`
* Device connectivity: `ONLINE` / `OFFLINE`
* API status: `UP` / `DOWN`
* Cloud server status: `UP` / `DOWN`
* MQTT server status: `UP` / `DOWN`

Use consistent status colors:

* Green: normal, online, up, working, OK
* Orange: warning or degraded state
* Red: faulty, offline, down, low battery, danger
* Grey: unknown, unavailable, or stale data

Add icons only if an icon library is already installed. Do not add an unnecessary heavy dependency.

### 3. Three-column equipment summary

Below the main monitoring section, show a responsive equipment-status grid.

Desktop and tablet:

* Three columns: `LEFT RTU`, `MCU`, `RIGHT RTU`

Mobile:

* Preserve readability using stacked cards or a horizontally scrollable compact grid.
* Avoid tiny text.

#### Row 1: power and availability

* Left RTU status: `ON` / `OFF`
* MCU status: `ON` / `OFF`
* Right RTU status: `ON` / `OFF`

#### Row 2: MCU telemetry

* MCU solar voltage, for example: `13.8 V`
* MCU solar current, for example: `1.25 A`
* MCU input-sensor status: `UP` / `DOWN`

#### Row 3: RTU battery comparator status

* Left RTU battery status: `OK` / `LOW`
* Middle cell may remain empty or show a simple note: `LM393 Comparator Input`
* Right RTU battery status: `OK` / `LOW`

Do not show exact RTU voltage. These are LM393 comparator digital results only.

Add a small information tooltip or help text:

`RTU battery status is detected by an LM393 comparator. LOW indicates that battery voltage has fallen below the preset threshold. The LVD may switch off the RTU to protect the 12 V solar battery.`

### 4. Single alert-annunciation row

Do not add a duplicated fifth row.

Use one annunciation section containing two responsive groups:

* `LEFT RTU ALERT ANNUNCIATION`
* `RIGHT RTU ALERT ANNUNCIATION`

Each RTU group must show three output controls:

1. Siren
2. Flash
3. Voice

For each output:

* Show the current state: `OFF`, `ACTIVE`, `TESTING`, or `SILENCED`
* Change button color when active
* Use a clear icon if available
* Provide a test action that triggers a `5-second pulse`
* While the five-second test is running, show a countdown or `TESTING`
* Disable repeated clicks while the test pulse is already active
* Show a loading state while a control command is being sent
* Show success or failure feedback after the API response

When an alarm is automatically activated by sensor data:

* Highlight the alarm button in red or orange depending on severity
* Show an `ACTIVE` badge
* Provide an operator action to turn off or silence the output
* Do not visually pretend that the underlying sensor condition has cleared
* If the danger condition still exists, keep a separate visible warning such as:
  `Danger condition is still active. Output has been silenced manually.`

Use one row only for both RTU annunciation groups. Do not repeat the same controls in another row.

Validation rules:

* Red danger level must not exceed `1000 mm`.
* Values must not be negative.
* Show inline validation errors.
* Disable Save while the settings are invalid.
* Ask for confirmation before saving changed threshold values.
* Display loading, saved, and failed states.

### 8. Stale data handling

Use `updatedAt` to detect stale values.

* Display the latest update time.
* If data is stale, show a visible warning such as `STALE DATA`.
* Use grey status chips for stale or unknown values.
* Do not show old data as confidently online or working.

Use an existing app convention for the stale threshold if one already exists. Otherwise, define a configurable threshold.
