# 6. Alarm Logic According to Sensor Configuration

## 6.1 Common delayed trigger rule

Never trigger immediately.

Use stable duration:

```text
Alert trigger only after configured condition stays true for trigger_delay_seconds
Danger trigger only after configured condition stays true for trigger_delay_seconds
Clear only after safe condition stays true for clear_delay_seconds
```

Default:

```text
trigger_delay_seconds = 60
clear_delay_seconds = 300
```

---

## 6.2 RS485-only logic

When only RS485 is enabled:

```text
If RS485 water_level_mm >= alert_level_mm for trigger_delay_seconds:
  status = ALERT_ORANGE

If RS485 water_level_mm >= danger_level_mm for trigger_delay_seconds:
  status = DANGER
  siren ON
  beacon ON
  voice announcement ON
  send danger event with note: "Danger triggered by RS485 water level sensor."

If RS485 water_level_mm < clear_level_mm for clear_delay_seconds:
  clear danger automatically
```

If RS485 fails:

```text
status = SENSOR_FAULT
send alert: "RS485 water level sensor not sending data."
do not trigger danger unless configured backup switch sensor exists
```

---

## 6.3 Switch-only logic

When only switch sensor is enabled:

Level 1 switch:

```text
If level_1_switch == CLOSED for trigger_delay_seconds:
  status = ALERT_ORANGE
  note = "Alert triggered by Level 1 switch sensor."
```

Level 2 switch:

```text
If level_2_switch == CLOSED for trigger_delay_seconds:
  status = DANGER
  siren ON
  beacon ON
  voice announcement ON
  note = "Danger triggered by Level 2 switch sensor."
```

Clear:

```text
If level_2_switch == OPEN and level_1_switch == OPEN for clear_delay_seconds:
  clear danger automatically
```

---

## 6.4 Both sensors enabled: dual-sensor logic

When both RS485 and switch sensor are enabled, input-side logic should primarily use AND confirmation where possible.

### 6.4.1 Alert level behavior

If RS485 crosses alert threshold but switch Level 1 is not yet triggered:

```text
status = ALERT_PENDING_VERIFICATION
show message = "RS485 water level crossed alert threshold. Waiting for Level 1 switch verification."
do not activate siren
show orange pending status on app
send telemetry but not danger alarm
```

If RS485 crosses alert threshold AND Level 1 switch is closed for trigger_delay_seconds:

```text
status = ALERT_ORANGE_CONFIRMED
show message = "Alert confirmed by RS485 sensor and Level 1 switch."
```

If Level 1 switch triggers but RS485 is below alert threshold:

```text
status = ALERT_SENSOR_MISMATCH
show message = "Level 1 switch triggered but RS485 level is below alert threshold. Check site or RS485 calibration."
```

This should be visible on app and logged.

---

### 6.4.2 Danger level normal confirmation

If RS485 crosses danger threshold AND Level 2 switch is closed for trigger_delay_seconds:

```text
status = DANGER_CONFIRMED
siren ON
beacon ON
voice announcement ON
note = "Danger confirmed by RS485 sensor and Level 2 switch."
```

---

### 6.4.3 RS485 says danger but Level 2 switch not triggered

This is a special mismatch condition.

If both sensors are enabled and:

```text
RS485 water_level_mm >= danger_level_mm for trigger_delay_seconds
AND
Level 2 switch is NOT closed
```

Then:

```text
status = DANGER_WITH_SENSOR_MISMATCH
siren ON
beacon ON
voice announcement ON
note = "RS485 sensor crossed danger level but Level 2 switch did not verify. Possible switch failure, obstruction under ultrasonic sensor, person/vehicle standing below sensor, or site issue. Check camera/site physically."
```

Important:

Even though verification failed, make danger alarm because water level may be high or one sensor may have failed.

App/PWA must show this as danger with warning note.

FCM notification example:

```text
DANGER: RUB043 RS485 crossed 500mm but Level 2 switch did not verify. Possible switch failure or obstruction. Check site/camera immediately.
```

Audit log must record this mismatch.

---

### 6.4.4 RS485 not sending data but switches detect water

If both sensors are enabled and RS485 signal is not sending valid data:

```text
rs485_status = FAULT
```

If Level 1 switch closes for trigger_delay_seconds:

```text
status = ALERT_WITH_RS485_FAULT
note = "Level 1 switch triggered but RS485 sensor is not sending data. Check RS485 sensor."
```

If Level 2 switch also closes for trigger_delay_seconds:

```text
status = DANGER_WITH_RS485_FAULT
siren ON
beacon ON
voice announcement ON
note = "Level 2 switch triggered but RS485 sensor is not sending data. Sensor 1 may be faulty. Check site physically."
```

FCM notification example:

```text
DANGER: RUB043 Level 2 switch triggered but RS485 sensor is offline/faulty. Siren activated. Check site physically.
```

Audit log must record this event.

---

### 6.4.5 Switch fault suspicion

If RS485 repeatedly crosses danger threshold but Level 2 switch never triggers across a configured mismatch duration:

```text
mismatch_duration_seconds default = 120
```

Then generate:

```text
event_type = SWITCH_SENSOR_POSSIBLE_FAULT
note = "RS485 crossed danger threshold but Level 2 switch did not trigger for 120 seconds."
```

But danger alarm remains active.

---

### 6.4.6 RS485 obstruction suspicion

If RS485 suddenly shows very high water level but both switches remain open and the reading is unstable:

```text
event_type = POSSIBLE_RS485_OBSTRUCTION_OR_FALSE_ECHO
note = "RS485 indicates high level but switches are open. Possible person, vehicle, animal, stone, or obstruction under sensor."
```

If RS485 crosses danger threshold continuously for trigger_delay_seconds, still activate danger alarm with mismatch note.
