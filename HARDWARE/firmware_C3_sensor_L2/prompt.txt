````markdown
# Codex Task: ESP32-C3 Ultrasonic Level Switch Sensor Module

## Objective

Build firmware for an ESP32-C3 based secondary water-level confirmation sensor.

This device will use a TTL ultrasonic distance sensor and provide two relay/contact outputs:

1. Level 1 Alert Output
2. Level 2 Danger Output

The goal is to make this ESP32-C3 module behave like a configurable two-level switch sensor, so the existing ESP32-S3 main controller, VPS backend, mobile app, PWA dashboard, and alarm logic can remain compatible with the earlier switch-type sensor design.

---

## 1. Hardware

### Controller

```text
ESP32-C3
````

### Sensor

```text
TTL ultrasonic distance sensor
```

Sensor wiring:

```text
Sensor VCC  → 5V or 3.3V as per sensor model
Sensor GND  → GND
Sensor TX   → ESP32-C3 UART RX
Sensor RX   → optional, only if sensor needs command input
```

If sensor TX is 5V TTL, protect ESP32-C3 RX using voltage divider.

Example:

```text
Sensor TX → 1k resistor → ESP32-C3 RX
ESP32-C3 RX → 2k resistor → GND
```

### Outputs

Two relay/contact outputs:

```text
Relay Output 1 = Low Level / Alert trigger
Relay Output 2 = Danger Level trigger
```

Recommended output behavior:

```text
Relay 1 ON when water level >= level1_threshold_mm
Relay 2 ON when water level >= level2_threshold_mm
```

Relay outputs should be usable as NO/COM dry contact input to the ESP32-S3 main MCU panel.

---

## 2. Default Thresholds

Default values:

```json
{
  "level1_threshold_mm": 200,
  "level2_threshold_mm": 400
}
```

Meaning:

```text
Water level >= 200mm → Relay 1 ON
Water level >= 400mm → Relay 2 ON
```

Both values must be configurable from the local HTTP configuration page.

## 3. Zero Level Calibration

The ESP32-C3 module must support zero-level calibration.

### Concept

The ultrasonic sensor measures distance from sensor face to ground/water surface.

During installation, user will open local web page, see the current sensing value, and click:

```text
Set Current Value as Zero Level
```

After this, the current measured distance becomes the reference zero.

Store this value:

```json
{
  "zero_distance_mm": 1234
}
```

Water level calculation:

```text
water_level_mm = zero_distance_mm - current_distance_mm
```

Example:

```text
zero_distance_mm = 1200
current_distance_mm = 1000
water_level_mm = 200
```

If water level calculation becomes negative, clamp to zero:

```text
if water_level_mm < 0:
    water_level_mm = 0
```

## 9. Relay Trigger Logic

Do not trigger immediately. Use stable delayed logic.

Default delay:

```text
Trigger delay: 60 seconds
Clear delay: 300 seconds
```

### Level 1 relay

```text
If water_level_mm >= level1_threshold_mm continuously for trigger_delay_seconds:
    Relay 1 ON
```

Clear:

```text
If water_level_mm < level1_threshold_mm continuously for clear_delay_seconds:
    Relay 1 OFF
```

### Level 2 relay

```text
If water_level_mm >= level2_threshold_mm continuously for trigger_delay_seconds:
    Relay 2 ON
```

Clear:

```text
If water_level_mm < level2_threshold_mm continuously for clear_delay_seconds:
    Relay 2 OFF
```

Optional hysteresis:

```text
Relay 1 clear below level1_threshold_mm - 30mm
Relay 2 clear below level2_threshold_mm - 50mm
```

Make hysteresis configurable later, but use sane defaults.

---

## 10. Sensor Reading Filter

Implement sensor filtering to avoid false triggers due to splash, vehicle movement, or temporary obstruction.

Sensor read interval:

```text
1 second or 2 seconds
```

Filtering:

```text
Take last 5 valid readings
Remove highest and lowest
Average remaining 3
```

Reject invalid readings:

```text
0
negative
out of range
timeout
CRC/frame error if applicable
```

If sensor reading invalid continuously for configured time:

```text
sensor_status = FAULT
Relay outputs should not newly trigger based on invalid data
Existing relay state should remain until valid clear or manual reboot/config
```

For demo, show sensor fault on local page.

## 11. Output Mode

Relay output can be active HIGH or active LOW depending relay board.

Make this configurable in code:


Or store in config later.

Default:

```text
Most relay boards are active LOW.
```

So firmware should support both.

## 14. Integration With Main ESP32-S3

This ESP32-C3 module behaves like a two-level switch sensor.

Main ESP32-S3 sees:

```text
C3 Relay 1 contact → S3 Level 1 input
C3 Relay 2 contact → S3 Level 2 input
```

So existing S3 logic remains same:

```text
Level 1 input closed → Alert verification
Level 2 input closed → Danger verification
```

No change required in main S3 app/backend logic except updating description:

```text
Secondary sensor type = Smart Ultrasonic Level Switch Module
```

## 15. Safety Requirements

* Never lose threshold config after power cut.
* Do not trigger relay instantly; use delay.
* Do not clear relay instantly; use clear delay.
* Clamp negative water level to zero.
* Show current value clearly on local page.
* Require password before config.
* Password input should have view/hide eye.
* Settings must be saved in NVS.
* Device should start local AP even if no internet exists.
