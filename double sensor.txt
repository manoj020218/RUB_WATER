# FloodGuard Firmware + VPS + APK Update Spec

## Double Sensor Input Model: DYP RS485 US Sensor + Switch Type Level Sensor

Implement a double sensor input model in FloodGuard firmware, VPS logic, and APK UI.

There are two possible water-level input sources:

1. **DYP Ultrasonic Sensor**

   * Firmware/internal name: `dyp_us_sensor`
   * APK/UI display name: **RS485 US Sensor**
   * This is the primary water-level sensor.
   * It provides measured water level in mm.

2. **Switch Type Level Sensor**

   * Firmware/internal name: `switch_level_sensor`
   * APK/UI display name: **Switch Type Sensor**
   * This has two adjustable level points:

     * `switch_l1` = Orange level confirmation
     * `switch_l2` = Danger level confirmation
   * This works as digital confirmation input.
   * L1 means Orange level crossed.
   * L2 means Danger level crossed.

Remove all pump-related logic, UI fields, MQTT topics, API fields, logs, and relay references from firmware, VPS, and APK. This project is not using pump control.

---

Firmware WebUI must have sensor mode configuration. Same setting must also be configurable from VPS by MQTT or HTTP.

```js
  NO_SENSOR
```

APK display:

# 3. Case 1 — Both Sensors Active

If user sets:

```js
sensor_mode = BOTH_ACTIVE
```

then:

* DYP RS485 US Sensor is primary sensor.
* Switch Type Sensor is confirmation sensor.
* Final alert can be:

  * Confirmed Orange
  * Suspected Orange
  * Confirmed Danger
  * Suspected Danger
  * Normal
  * Sensor conflict / possible sensor fault / possible obstruction

## 3.1 DYP detects Orange first, Switch does not confirm

Condition:

```js
dyp_level_mm >= orange_level_mm
AND switch_l1 == false
AND switch_l2 == false
```

Action:

1. Start timer:

```js
orange_confirmation_timer_started_at
```

2. If within `sensor_confirmation_wait_sec`, switch L1 or L2 becomes active:

```js
switch_l1 == true OR switch_l2 == true
```

then:

```js
alert_level = ORANGE
alert_status = CONFIRMED
reason = "DYP Orange level confirmed by Switch Type Sensor"
```

Trigger:

* Right RTU relay according to Orange logic
* Left RTU relay according to Orange logic
* APK Orange alert
* VPS log

3. If timer exceeds `sensor_confirmation_wait_sec` and switch still does not confirm:

```js
alert_level = ORANGE
alert_status = SUSPECTED
reason = "RS485 US Sensor crossed Orange level but Switch Type Sensor did not confirm within configured time. Possible Switch Sensor fault or obstruction/person/object below RS485 US Sensor."
```

Still show Orange alert in APK, but mark it as suspected/unconfirmed.

Trigger:

* Orange alert in APK
* Right/Left RTU trigger according to Orange alert logic
* VPS log with warning message

Log event:

```js
{
  event_type: "ORANGE_ALERT_UNCONFIRMED_DYP_FIRST",
  alert_level: "ORANGE",
  alert_status: "SUSPECTED",
  dyp_level_mm,
  switch_l1,
  switch_l2,
  wait_time_sec,
  message: "RS485 US Sensor crossed Orange level but Switch Type Sensor did not confirm. Possible Switch Sensor fault or obstruction/person/object below RS485 US Sensor.",
  timestamp
}
```


```js
  source: "BOTH_SENSOR" | "DYP_ONLY" | "SWITCH_ONLY" | "NO_SENSOR"
```

```js
if sensor_mode == NO_SENSOR:
```

Both confirmed and suspected alerts must trigger relay/alarm because waterlogging risk is higher priority than sensor mismatch.

# 14. Suggested Firmware Pseudocode

```cpp
enum SensorMode {
  BOTH_ACTIVE,
  DYP_ONLY,
  SWITCH_ONLY,
  NO_SENSOR
};

enum AlertLevel {
  NORMAL,
  ORANGE,
  DANGER
};

enum AlertStatus {
  CONFIRMED,
  SUSPECTED,
  CONFIRMED_BY_SINGLE_SENSOR,
  DISABLED
};

struct AlertDecision {
  AlertLevel level;
  AlertStatus status;
  String reason;
  String source;
};

AlertDecision evaluateAlert() {
  if (sensorMode == NO_SENSOR) {
    return {NORMAL, DISABLED, "Automatic alert disabled because no sensor is configured", "NO_SENSOR"};
  }

  if (sensorMode == DYP_ONLY) {
    if (dypLevelMm >= dangerLevelMm) {
      return {DANGER, CONFIRMED_BY_SINGLE_SENSOR, "Danger by RS485 US Sensor only", "DYP_ONLY"};
    }
    if (dypLevelMm >= orangeLevelMm) {
      return {ORANGE, CONFIRMED_BY_SINGLE_SENSOR, "Orange by RS485 US Sensor only", "DYP_ONLY"};
    }
    return {NORMAL, CONFIRMED_BY_SINGLE_SENSOR, "Normal by RS485 US Sensor only", "DYP_ONLY"};
  }

  if (sensorMode == SWITCH_ONLY) {
    if (switchL2Active) {
      return {DANGER, CONFIRMED_BY_SINGLE_SENSOR, "Danger by Switch Type Sensor L2", "SWITCH_ONLY"};
    }
    if (switchL1Active) {
      return {ORANGE, CONFIRMED_BY_SINGLE_SENSOR, "Orange by Switch Type Sensor L1", "SWITCH_ONLY"};
    }
    return {NORMAL, CONFIRMED_BY_SINGLE_SENSOR, "Normal by Switch Type Sensor", "SWITCH_ONLY"};
  }

  if (sensorMode == BOTH_ACTIVE) {
    return evaluateBothSensorLogic();
  }
}
```

Implement `evaluateBothSensorLogic()` with timer-based confirmation for Orange and Danger.

Danger must always override Orange.
